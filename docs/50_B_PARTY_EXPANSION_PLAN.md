## 2. 各阶段切入点与测试

### 阶段 V — 内置语音

见 47 号文档第 2–5 节，不在此重复。

完成标准：
- 注入音源的 2P/4P 转发测试通过；

### 阶段 8 — 表现与手感

**切入点：**
- `src/Presentation/HeadView.cs`：负责晃动、反光和拉丝。
- `ContactFeedback.cs`、`ToolFeedback.cs`：负责敲击声和冰碴。
- `ExperimentView.cs`：负责委托物下陷和聚光灯效果。
- `LandingFeedback.cs`：负责单侧可见的提示。
- `PartyGallery.cs`、`GalleryStore.cs`：负责合影、改造前照片、成对挂墙和玩家头像。
- 头发减少的统计，用 `ImpactRecording.cs` 里已有的 `initialBarberMass`。

**测试：**
- 截图检查（中英文）：软、硬、胶、冻四种状态的表现，委托物下陷，合影倒数。
- Core 测试：成对照片的元数据；头发减少百分比的计算。
- 截图显示纯表现层的变化不改变任何权威状态：比较 `Wire.Encode` 的结果，做法同 `Hud.cs` 中切换语言时的检查。

### 阶段 9 — 身体、流动与协作道具

**切入点：**
- **倒地与拍醒**：`PartyAccidents.cs`，沿用现有冻结 / 粘手的状态模式和 3 秒免疫。
- **扔与接**：
  - 在 `Session` 的丢弃 / `Drop` 路径上增加蓄力投掷；
  - 物件的飞行复用 `PhysicalProps.Tick` 的下落逻辑。
- **转椅子**：
  - `Session.AdjustChair` 和 `Buttons` 需要新增旋转输入；
  - 修改顾客根变换后，确认工具查询、支撑探针和渲染都用同一个变换。
- **协作道具**：新增道具定义和两人握持状态：
  - 管线喷枪：需要喷头和罐子两件，外加管子的距离约束；
  - 双人大剪刀：由房主比较两人输入的时间戳。
- **合抬大件**：需要“两人同时握持”的状态。
- **扶梯子**：`LadderState` 需要增加“扶梯人”；梯子晃动只偏移工具作用点，不影响镜头。

**测试：**
- Core 测试：
  - 倒地触发和拍醒；
  - 投掷的轨迹和自动接住；
  - 转椅子后，探针和工具命中的一致性；
  - 协作道具只在理发师人数 ≥ 2 时生成；
  - 双人剪刀在不同时间差下是否生效；
  - 管子超过长度后脱开。
- 引擎测试：用真实输入完成投掷、接住、双人剪刀，确认镜头没有被移动。
- 网络测试：2P/4P 远端完成双人剪刀和管线喷枪；带种子的跨境劣化测试下，同步容差仍然有效。

**检查点 D**：打包并验证。

### 阶段 10 — 目标卡、可测属性与误会生成器

**切入点：**
- 新增 `src/Core/StyleAttributes.cs`：纯函数，读取 `HairVolume` 的密度、材质占比、附着的假发和委托物位置。
- 新增 `src/Core/TargetCards.cs`：卡池数据、道具读法数据、带种子的发牌。
- 小费改为 `PartyResults.Evaluate`：有目标卡时，用属性匹配取代原来的固定小费。
- 道具台和道具实体复用 `PropState`，新增一种类型。
- 私密发送复用 `src/Bootstrap/PartySecrets.cs` 的定向私发路径。
- AI 顾客的反应接到 `CustomerRemarks` 和注意力或反应系统，声音走 V-16。

**测试：**
- Core 测试：
  - 每个属性都用固定体积用例测试，必须包含“两只角”和“宽三角形”的区分；
  - 发牌规则的三条约束，用多个种子批量验证；
  - 情绪卡能解析成对应的隐藏属性；
  - 小费不会是负数。
- 网络测试：确认目标卡只发给有权看到的玩家（G-8）。

### 阶段 11 — 真人顾客

**切入点：**
- 在 `PlayerState` 上增加“顾客角色”标记。
- 共享头的权威变换在顾客坐下时跟随椅子，站起来后跟随顾客的身体。复用阶段 2 离店时移动头部的路径，以及“离店中的头不与玩家身体碰撞”这条既有规则。
- 顾客输入映射（R11-4），需要客户端预测和房主校正：
  - 坐着时的眼睛视角与站起来走动分开处理；
  - 身体移动沿用现有的移动预测。
- `Sculpting.cs` 和工具查询：增加“顾客不能作用于共享头”的排除条件。
- 镜头稳定（R11-8）：顾客的相机不跟随本能反应的姿态。
- 结算和揭晓：`ExperimentHud.cs`、`PartyGallery.cs` 负责并排展示和逐项 ✓ / ✗；扔奶油派是本地表现，派的命中由房主判定。

**测试：**
- Core 测试：
  - 顾客轮换；
  - 断线后由 AI 接管；
  - 顾客的工具无法修改共享头；
  - 表达动作让头部姿态变化的幅度，以及扶头时的缩小系数；
  - 离店 20 秒超时后在原地判定；
  - 起身对抗：按键计数、每秒上限、多人叠加的递减系数、冷却时间，以及离店时累计拖延的上限；
  - 点赞和狗屎不进入任何分数或收入。
- 引擎测试：真实输入完成点头、摇头、转头、拍开、起身、坐下；本能反应时顾客的镜头保持稳定。
- 网络测试：
  - 4P 真人模式完整一局，包括远端顾客走动和理发师追着施工；
  - 带种子的跨境劣化测试，要同时看“顾客走动中的头”和玩家的运动指标；
  - 变声管线在真实会话中的表现。

**检查点 E**：打包，并在包说明中写清楚真人顾客的操作方式。

### 阶段 12 — 变局卡

**切入点：**
- 新增 `src/Core/TwistCards.cs`：卡的定义、每张卡的适用条件、抽卡规则（相邻两局不同类别）。
- 每张卡实现为一个修改器，提供“开局启用 / 结算关闭”两个钩子。
- 需要改渲染的卡（镜像世界、蒙眼施工、只有一个人看得见），只在各客户端的表现层实现，权威状态不变。
- 雾镜作画：镜面的雾浓度由房主权威决定；画线按线段同步，并设置数量上限。
- 迷你示范：复用 `MiniatureModel`（B 版目前把它移除了，这张卡需要重新放出头模）。

**测试：**
- Core 测试：
  - 抽卡规则和适用条件的完整矩阵（人数 × 顾客模式）；
  - 限次提问的计数；
  - 反话局只在别人的画面里对调；
  - 反转局选项的判定；
  - 家属卡的双卡结算。
- 截图检查（中英文）：每张卡的卡面，以及蒙眼施工、镜像世界的效果。
- 舒适度检查：镜像世界必须由 owner 和朋友内测，没通过就默认关闭。

### 阶段 13 — 世界角色与场次

**切入点：**
- 店猫：新增一个房主权威的简单状态机，包括“预兆 → 行动 → 离开”，复用 `PropState` 的物理。
- 被粘住后拖走：接到 `PartyAccidents` 的粘手状态和离店路径上。
- 清醒度：在 `TickAttention`（`Experiment.cs`）里增加困倦一端。
- 回头客场次：在 `NextRound` 中增加“保留共享头”的分支，并加入两局之间的自然生长。

**测试：**
- Core 测试：
  - 猫出现的概率、预兆时长、每局最多出手次数；
  - 被拖速度的上限；
  - 困倦和惊醒的状态切换；
  - 回头客场次中，共享头跨局保留。
- 网络测试：2P/4P。

**检查点 F**：打包并验证。

## 3. 风险

| 风险 | 缓解 |
|---|---|
| 真人顾客控制共享头，与客户端预测冲突，跨境时出现抖动 | 头部变换只由房主决定，客户端按时间插值；阶段 11 必须通过劣化测试中的运动指标 |
| 双人剪刀的同步在跨境延迟下判定失败 | 用输入时间戳和容差判定，而不是用到达时间；劣化测试覆盖 |
| 风格属性评估不准，比如尖角数量误判 | 先写固定用例；阈值可以调整；结算时显示逐项 ✓ / ✗，便于试玩中发现问题 |
| 私密信息泄漏 | G-8 规定的自动检查，与秘密任务使用同一套机制 |
| 视角类变局卡导致晕眩 | G-12：开关、内测，没通过就默认关闭 |
| 内容量大，导致每个阶段的回归时间变长 | 每个阶段只跑受影响的网络检查；检查点才跑完整打包验证 |

## 4. 真人验收的观察点（给 owner）

| 阶段 | 看什么 |
|---|---|
| 8 | 玩家描述问题时用的是“这里软、会晃”，还是在读数字；合影时有没有人摆姿势 |
| 9 | 有没有人自发喊“扔给我”；被拍醒的人是在笑还是在烦；转椅子时是笑着抢，还是觉得烦躁；双人剪刀能不能配合成功 |
| 10 | AI 模式下，玩家会不会说“他好像要……”；揭晓时是笑还是觉得冤 |
| 11 | **真人顾客那一局结束后，有没有人主动要求下一局当顾客**；有没有“做到一半才发现理解错了”；顾客示范时是好笑，还是打断别人、让人烦躁 |
| 12 | 哪张卡被抽到时有惨叫或大笑；哪张卡让大家的做法明显改变；想再抽哪张 |
| 13 | 猫出手后大家是笑还是烦；回头客场次最后回放时的反应 |

2 人及以上固定使用真人顾客（owner 决定）。试玩时特别观察：2 人局里，只有一名理发师时忙不忙得过来，以及起身对抗会不会被刷成连点比赛。
