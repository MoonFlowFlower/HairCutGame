## 1. 设计原则（讨论中确立的）

1. **所有人做同一件事。** 始终只有一颗共享的头，不做每人一个顾客。
2. **胡闹之后能救回来。** 意外是节目，不是秒杀。
3. **约束由系统或沟通渠道本身来执行，不靠玩家自觉。** 靠自觉的规则既无法检测、无法计分，违反后的负面感受也很大。
4. **“完成与否”由物理功能判定；风格只使用系统测得出的属性。** 抽象的文字可以当包装，但背后必须对应到可测量的属性。
5. **学 How to Fish 的底层性质，不学“步骤多”。** 那些性质是：
   - 物件一看就懂；
   - 玩家的身体本身就是故事素材；
   - 失败有好笑的救援仪式；
   - 世界里有自己行动的角色；
   - 物件在人与人之间流动；
   - 后果会留下痕迹。

   不做强制的“洗 → 剪 → 吹”流程。
6. **任何两局之间至少有一样不同**：顾客（物种、属性、起始发型）、目标卡或变局卡。
7. **一局只加一个规则变化**，开局用一句话宣布。基础玩法还不好玩时，不要叠加变化。
8. **协作道具不能是唯一解法。** 一个人也能用，只是更慢；两个人配合更快、更好笑。
9. **被波及的效果要短，并且能自动恢复。** 不强制移动或旋转玩家的镜头（同 44 号文档的 G-4）。

## 2. 人数与模式

- 【已决定】单人模式保留，定位为练习和教学，由 AI 当顾客。新机制只要求单人局能跑、不出错，不为单人专门做平衡。
- 【已决定】**协作道具在理发师人数 ≥ 2 时出现。**
- 【已决定】做游戏内置语音，所有人改用游戏语音；麦克风限制已经解除（见 47）。

## 3. 【优先候选】C9 真人顾客（合作式的“哑巴顾客”）

**定位：** 合作式的不对称沟通。顾客玩家和理发师同一队，结果共享。乐趣来自“知道答案的人不能说，能动手的人不知道答案”。参考《Keep Talking》《机密代号》《Mysterium》。顾客玩家没有单独的分数，把委托搞砸也拿不到任何好处。

**一局的流程：**

1. **看卡，约 5 秒。** 只有顾客玩家能看到目标卡。目标卡包含功能委托，以及 2–3 个可测量的风格属性（见第 5 节）。
2. **比划，约 20–30 秒。** 顾客可以下椅子走动，拿道具举给大家看；理发师也可以举着东西问“是这个吗？”。
3. **坐下开工。**
   - 顾客的**主动动作**由玩家控制：点头、摇头、扭头、照镜子。
   - **本能反应**仍由系统控制：被烫到会缩、打喷嚏、受惊吓。这样 `docs/17`、`docs/32` 的“活顾客”规则继续有效。
   - **表达有代价**：顾客的头动得越多，理发师越难做；他一站起来，施工就得暂停。
4. **离店检验和揭晓。**
   - 离店检验按 43–45 号文档进行。
   - 揭晓时，把目标卡和成品照片并排展示。
   - 委托完成与否，由物理功能判定。
   - 风格匹配只影响顾客反应和小费。

**顾客的身体与示范**（2 人局同样适用，所以 2 人局也有“挤在一起的混乱”）：

- **顾客不能改自己的头。** 实现上沿用 `Sculpting.cs` 中“玩家不能编辑自己头发”的同类判断 **[观察]**。
- 顾客可以拿工具，在别的东西上示范：
  - **理发师的头发**：最推荐，把理发师的头当画板。玩家头发在整场比赛内保留 **[观察]**。
  - 迷你头模（`MiniatureModel` 已经存在）。
  - 道具或地面。
- 示范时误伤理发师，按队友小事故处理（44 号文档 R6-1）：时间短、能恢复、写进动作记录。
- 坐着时，顾客可以把模具或假发扶在自己头上。他看不清，得听理发师指挥。

**顾客的表达手段要刻意少：** 点头、摇头、扭头给人看某一面、举道具、站到某个道具旁边、“拍开”理发师的手。**不提供**指向头上某个位置、比划数字、打字这些手段。

**声音：** 顾客的原始声音**不传给其他人**，只发送响度、音高、节奏，其他人听到的是按物种合成的“歪比巴卜”或鸟叫，只剩语气。技术管线是 47 号文档的 V-12 到 V-16（C16）。

**揭晓时的回敬仪式**（施工过程中，顾客没有任何伤害理发师的手段）：

- **推荐：** 所有人互扔奶油派。纯外观效果，糊在脸上的奶油会进合影。
- **可选：** 顾客回赠一刀。揭晓时顾客有 5 秒，用一件工具处理某个理发师的头发，这被当作每局固定的仪式，不是惩罚。
- **不做：**
  - 只给某一个理发师点赞或扔东西，因为这会让理发师之间开始竞争；
  - 扔狗屎（以后最多做成一个皮肤）。

**轮换：** 每局换一个人当顾客。

## 4. 误会生成器

目标是让误会**由规则稳定地产生**，比如顾客想要“两只角”，理发师做成了“一个三角形”。

1. **一物多义。** 每件道具有 2–3 个都很显眼的特征，目标只取其中一个。
2. **桌上没有完美的道具。** 每局随机摆出约 6 件，没有任何一件能单独表达整个目标（参考《Mysterium》随机的手牌）。
3. **目标有多个维度，反馈只有“对 / 不对”。** 目标由特征、数量、位置组合而成，顾客只能对整体点头或摇头。
4. **解释要付出代价。** 点头会晃动头部；站起来，施工就暂停。

**中文发型俗名是天然的双关素材**，比如飞机模型（停机平台 / 飞机头）、锅盖（平顶 / 锅盖头）、小鸡（鸡窝 / 鸡窝头）、马（马尾）、丸子（丸子头）、蘑菇（蘑菇头）、木板（板寸）、鞭炮（冲天辫）。

一般的多义道具也可以用，比如牛、叉子、皇冠、蜗牛、甜甜圈、冰淇淋、犀牛、仙人掌。

英文版需要另做一套道具池，比如 beehive、mullet、bowl cut、duck tail。

**数据形状：**

- `TargetCard`：功能委托，加上 2–3 个可测量的属性。
- `PropReading`：每件道具有多个“读法”标签，每个标签对应一个属性取值。

发牌规则：

- 目标的每个属性，至少能被一件道具的某个读法覆盖；
- 没有任何一件道具能覆盖目标的全部属性；
- 每件道具至少带一个干扰读法。

## 5. 可测量的风格属性

**[推断]** 以下属性都能从现有的体积和材质数据算出来，精度要在实现时逐项验证。

| 属性 | 怎么测 |
|---|---|
| 高度（低 / 中 / 冲天） | 体积的最高点 |
| 左右对称，或偏向一侧 | 左右两半的体积差 |
| 重心在前还是在后 | 体积重心的位置 |
| 尖角数量（0 / 1 / 2 / 3+） | 头顶高度图的局部最高点，加上最小突出高度阈值 |
| 材质状态 | 湿 / 冻 / 焦 / 胶 / 新生各自的占比（`Materials.cs`） |
| 有没有假发 | 共享头上是否附着了 `Wig` 头 |
| 委托物的位置 | 相对头部的前 / 后 / 左 / 右 / 顶 |
| 总体积 | 体积质量 |

- **情绪卡**（比如“看起来刚失恋”）只是文字包装，背后对应一组隐藏属性，例如“湿的占比高、高度低、没有尖角”。揭晓时把这组隐藏属性亮出来，本身就是一个笑点。
- **程度卡**（比如“整齐 ←→ 爆炸，目标 80%”）对应单个属性上的一个目标区间。

## 6. 每局的规则变化（“换脑子”）

每局最多抽一张变局卡，相邻两局尽量来自不同类别。**只保留由系统执行的变化。**

**A. 改变沟通渠道**

- **雾镜作画**：吹风机和喷壶会让镜子起雾，顾客只能用手指在雾上画。雾会慢慢散。
- **镜像世界**：顾客看到的画面左右颠倒。需要内测是否会晕。
- **迷你示范**：顾客用 10 秒、一件笨拙的工具，在迷你头模上做出示意模型。
- **只能用道具**：系统禁用点头和摇头。
- **反话局**：顾客的点头在别人眼里显示为摇头，反过来也一样。
- **限次提问**：理发师把道具举到顾客面前算一次提问，每局最多 N 次，由系统计数。

**B. 改变信息分布**

- **反转**：目标只给理发师看。顾客的眼睛被头发挡住，揭晓时由他来猜这是什么造型。
- **挑剔的家属**：4 人局中，一名玩家扮演顾客家属。家属可以正常说话，但手上是另一张需求卡。
- **只有一个人看得见**：只有一名理发师能看到顾客在比划，他再转述给其他人。
- **蒙眼施工**：理发师看到的头上盖着一块布，只有顾客能从镜子里看到真实情况。只改各客户端的渲染，不改权威状态。
- **各知一半**：目标图在顾客后脑勺上，操作说明书在顾客手里，双方互相依赖。

**C. 改变角色关系**

- **顾客帮手**：顾客能扶模具、举镜子，但他的手只能在“表达”和“帮忙”之间二选一。
- **顾客睡着了**：适用于 AI 顾客。顾客会说梦话给出含糊的线索，并用 V-16 的物种声音播放。

**D. 改变物理世界**（优先级最低）

- 停电、地板倾斜、风扇、低重力。

**场次结构（可选）**

- **F1′ 回头客局**：同一位顾客连续回来 3–4 局，每局从上一局的成品开始，换新的目标卡。场次结束时回放这颗头的“一生”。
- owner 的默认设定是每局换一位新顾客，所以这只作为一种可选的场次类型。
- 它需要一个“保留共享头”的开关：当前每局开始都会重置头发 **[观察，`NextRound` → `ResetCustomer`]**。

## 9. 已撤回或不做

| 项目 | 原因 |
|---|---|
| 每人一个顾客；“平时分开、Boss 才一起” | 违背原则 1 |
| 把整个目标藏起来，让大家猜电脑的意图 | 猜电脑不好玩；这个乐趣改由真人顾客来实现 |
| 靠玩家自觉的规则卡（只准唱歌、禁词、全员静音、只说英语、成语、三个字） | 无法检测，违反后的负面感受大 |
| 额头贴纸 | 难以想象节目效果，也无法检测 |
| 领地、延迟生效 | owner 判断不好玩 |
| 施工中顾客伤害理发师 | 合作会变成对抗 |
| 只给某一个理发师点赞或扔东西 | 会引发个人竞争 |
| 靠升级获得新鲜感；只是把需求卡换得更奇怪 | 只改数值或内容，不改玩法；升级仍在排除范围内 |
| 传话接龙 | 大家都看得见每一局的成品，没有信息差 |
| 内鬼或破坏者身份；小游戏合集 | 与“大家一起救回来”冲突，也会分散大家对同一颗头的注意力 |

## 10. 验证计划（零代码，一次聚会就能完成）

在当前版本里用人来扮演规则，由 owner 主持：

1. **哑巴顾客基础测试。**
   - 每局指定一人当“顾客心声”，他在语音里静音，站在镜子旁边。
   - owner 私下给他一张目标卡。当前只有直升机委托，所以目标卡写成附加要求，比如“停机坪偏后”“必须用上假发”“一侧冻住”。
   - 他只能用视角上下晃（点头）、左右晃（摇头）、站到某个道具旁边来表达，也可以用自己的角色在理发师头上剪几刀来示范。
   - 局末，他竖起大拇指或者摇头，然后翻开目标卡。
2. **AI 顾客 vs 真人顾客对照。** 2 人局和 3–4 人局都做：AI 顾客、真人顾客各玩 2 局。
3. **变化卡试玩。** 抽 1–2 张能用人来模拟的卡，比如情绪卡、程度卡、反转、挑剔的家属。

**观察这些能直接看到的行为：**

- 每局出现几次集体大笑；
- **真人顾客那一局结束后，有没有人主动要求下一局当顾客**（最关键）；
- 大家有没有“做到一半才发现理解错了”；
- 揭晓时大家是笑，还是觉得冤；
- 2 人局的理发师是忙不过来，还是觉得孤单；
- 顾客示范时，场面是好笑还是被打断、变得烦躁；
- 第三局还有没有兴趣。

**决定规则：** 某个人数下，如果真人顾客局的集体大笑明显更多，并且有人主动要当顾客，那么这个人数就默认使用真人顾客；否则仍以 AI 顾客为默认，真人顾客作为大厅里的可选项。测试有效的部分，再写成正式需求交给 Codex。
