> 状态：owner 于 2026-09-30 确认的**规划方向**，尚未实施。本文说明“为什么这样改、想要什么体验”。需求条目见 [44](44_B_PARTY_LOOP_REQUIREMENTS.md)，实施顺序、代码位置和验证方式见 [45](45_B_PARTY_LOOP_IMPLEMENTATION_PLAN.md)。

> 本文是 B 主线的延续，不是新变体，也不重启 A/B 实验。与 [42](42_B_DEVELOPMENT_BASELINE.md) 冲突时，以本文和 44/45 为准。本文明确放开的范围见第 7 节。

## 1. 一句话目标

> **一个人弄出了意外，队友喊他几句，大家顺手救了回来。最后看着丑得离谱、但确实能用的作品，一起笑。**

所有改动都要为这个画面服务。增加多少顾客、Boss 或工具都不是目标；目标是让“胡闹之后，大家仍然能把任务救回来”在每一局里反复发生。

## 2. 为什么要改（证据与判断）

标注：**[观察]** 来自日志或代码；**[推断]** 是设计判断；**[需试玩]** 需要真人验证。

- 首次朋友 2P 测试 6 局 0 成功，稳定时间从未超过 0；5/6 局有“太软”，5/6 局有“覆盖不足”。**[观察]**
  - 同一批数据里，每局都有人 40 秒以上没拿工具。owner 说明这主要是因为当时在讲解规则，所以**不作为设计问题处理**。
- 有一局，队友的火焰枪点火后，火灾规则每约 3 秒 +25 伤害，几秒内就超过 50。施工中的 HUD 不显示伤害，玩家到结算才知道原因。**[观察]**
  - 代码位置：`Session.cs` 烧着超过 12 块时触发 `Incident(...,25)`；`Experiment.cs` 的 `LandingBlockers` 在 `Job.Penalty>=50` 时持续阻止成功。
  - 这与“不过火还能过关”直接冲突。
- 直升机永远降在头顶正中心，检测是一个固定的 3×3 方阵，需要 9 点里至少 7 点接触。所以正确答案其实只有一块固定位置的平台。**[观察，`Experiment.cs` `LandingProbes`/`TickFlight`]**
- 硬度要等直升机接触后才看得出来。**[观察]**
- 头发区域的来源字段 `Patch.Source` 只记录最后一次作用者，火势蔓延还会继承来源。它不能当作品署名，也不能用来判罪魁。**[观察，`Hair.cs`]**
- 胶水只在 1 局用过，液氮从未使用。**[观察]**

## 3. 设计原则

1. **所有人做同一件事。** 永远是一颗共享的头，不做每人一个顾客，也不做“平时各做各的、Boss 才一起”。派对的混乱和节目效果来自大家挤在同一个东西上。
2. **目标要清楚，解法要宽，后果要看得懂。** 玩家应该能说出“别动这里，这里要承重；旁边你随便弄”，也应该偶尔发现“你弄的那个怪东西，居然帮我们过了”。
3. **核心要求是一个功能，不是一块规定好的施工圈。** 显示的是“东西放在哪里、哪里缺支撑”，而不是“在圈里填成标准平台”。作品可以长得完全不同，只要实际能用。
4. **外围也和任务有关。** 乱毛会影响重心、视线、工具操作和掉落物；朋友的装饰可能碍事，也可能变成补救材料。这些影响要可预测、可挽回，一次失手不能毁掉整局。
5. **胡闹可以救回来。** 普通事故只影响钱。真正会终止委托的危险必须提前预警、留出足够的抢救时间，救不回来时清楚收场。
6. **结算分层。** “委托完成了吗”是明确的是或否；作品的个性另外通过顾客反应和小费体现。轻微恶作剧不能总以扣钱收场，有些怪作品还能拿到额外赏钱。
7. **点名要忠于事实。** 只展示明确发生过的动作（“A 点火、B 灭火、C 加固”），让玩家自己笑着争论。系统不根据“最后碰过这里的人”判定罪魁。
8. **网络卡顿、镜头猛拉、操作被长时间剥夺都不算乐趣。** 所有“被波及”的效果都必须短、能自动恢复，而且不能强行移动玩家的镜头。

## 4. 新的一局

```
顾客进门、坐下（后期可能带随机初始头发状态）
  → 桌上摆着这单的委托物（如 RC 直升机）和可用的道具（模具、假发、生长剂瓶）
  → 大家自由施工；任何人随时可以把委托物拿起来放到头上试
      · 放上去后实时显示稳不稳、哪里缺支撑
      · 顾客的小动作、头发重心的变化都可能让它滑落，掉了再捡起来就行
  → 时间快到时，顾客看表、摸外套（预兆）；有人扶住他的头，可以把他按回去争取几秒（次数有限）
  → 顾客起身，走到镜子前，再走向门口：这就是最终物理检验
      · 玩家全程可以操作：跟着走、扶头、补胶、冻住
  → 走到门口时委托物仍在头上且有支撑，就算“完成”
  → 顾客对着镜子给出反应，结算基本工钱和小费；系统拍照，列出事实动作记录
  → 照片（成功和失败都挂）进入照片房间
```

与现有 B 相比：

- **委托物从“按钮呼叫、自己飞来”改为“摆在桌上，玩家拿去放”。** 好处是所有委托都能套用（鸟和蛋、猫、麦克风架），每个人随时都能测试或恶作剧；放置位置和朝向由玩家决定，不再有固定施工圈。
- **收尾压力从“直升机逼近”改为“顾客要离店”。** 离店的走动本身就是物理检验，而且会自然形成全员围着一个会走动的顾客手忙脚乱的高潮。
- 现有的注意力（`?`/`!`）、扶头、失败部位反馈、回放和网络基础设施全部保留。注意力系统因此更有意义：顾客一扭头，头上的东西可能滑下来。

## 5. 各系统的意图

| 系统 | 想产生的玩家行为 / 画面 |
|---|---|
| 可见边界与顾客实时反应 | 顾客喊“好烫！”时，有人冲过去灭火；玩家事后会学顾客的台词 |
| 委托物上桌与离店终检 | 有人偷偷提前把直升机放上去；最后四个人护送顾客出门 |
| 生长剂按瓶计量 | “你那瓶还剩多少？”；一个人浪费光自己那瓶，别人手里的还在 |
| 假发补丁 | 用一顶很丑的假发加胶水临时撑住，结果过了 |
| 碎发回收 | 把地上的碎发吸起来喷回去，救回烧掉的一角 |
| 模具 | 一人扶模具、一人喷；模具被打穿，头发从洞里长出一根怪刺，结果这根刺刚好能用 |
| 重心歪头 | 一边堆太多，顾客的头慢慢歪过去；另一边的人赶紧配重 |
| 组合发现 | “冻住再砸会碎！”第一次出现时大家都在喊 |
| 队友小事故 | 被液氮冻住 2 秒，队友敲一下就碎开；头顶着火，队友拿喷壶来救 |
| 秘密任务 | 结算时揭晓：“原来那一下是故意的！” |
| 照片房间 | 开局前在房间里看旧照片，指着某张失败照片笑 |

## 6. 已否决 / 推迟

- **否决**：每人一个顾客；平时分开、Boss 才一起做。
- **推迟为试验**：短单（一天多位顾客）、每位顾客只给 4–5 件工具。触发条件：做完阶段 1–4 后，若 4P 试玩（不含讲解期）里每位顾客期间仍有人闲置 20 秒以上，就把短单提前。
- **推迟到内容阶段**：多解的新委托（鸟巢）、随机初始头发状态、不同顾客的特性、随机 Boss。
- **仍未授权**：花钱买装备或成长系统、排名式个人奖项、固定职业或分工、更多精细雕刻笔刷。钱暂时只用来展示结果。
- **2026-09-30 追加**：麦克风限制已经解除，改做游戏内置语音，见 [47](47_B_IN_GAME_VOICE.md)。
