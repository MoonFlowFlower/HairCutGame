## 启动与检查

在仓库根目录使用 PowerShell 7：

```powershell
./scripts/build.ps1
./scripts/run_b.ps1
./scripts/run_b.ps1 -Mode Host -Port 7777
./scripts/run_b.ps1 -Mode Join -Address 房主地址 -Port 7777
./scripts/run_4p_local.ps1
./scripts/verify_b.ps1 -Network
```

`run_solo.ps1`、`run_host.ps1`、`run_client.ps1`、`run_4p_local.ps1` 以及不指定 Variant 的 `run_ab.ps1` 均选择 B。Lab / Laundry / Materials 和底层旧 QA 夹具保留原用途；直接调用 Godot 或在编辑器调试主线时显式传入 `--v06-variant-b`。本次不改变底层无变体参数的旧测试语义。

默认验证保留共享核心、引擎和 B 网络检查；A 专属整局检查仅在 `verify_v06.ps1 -Network -ArchivedA` 时运行。归档不意味着删除共享回归，也不要求每个文档修改重跑长测。

## 后续真人验收

以 B 连续多局为主，观察目标是否清楚、顾客注意力是否可理解和利用、靠近的直升机是否形成可应对的压力、操作与失败反馈是否公平、团队是否自然协作。网络异常场次仍需单独标注。

本轮优先观察这些行为：第一次失败后，玩家能否自己指出部位和原因，换一种施工操作并再次试落；呼叫前是否主动沟通、接触时是否有人继续有效补救；第二、三局是否仍会换工具、交接处理同一处问题，还是一人包办、其他人长期围观。记录材料耗尽发生在什么操作之后、是否能预见。两人和四人分别测试；不要把笑声、截图或通关本身等同于合作乐趣提升。

当前候选已修正快速修补后的旧降落提示和小额余量的虚假“未命中”反馈。冻结包附 `B_THREE_ROUND_PROTOCOL.txt` 与 `B_THREE_ROUND_RECORD.csv`，源文件在 `docs/packaging/`；四位朋友先 2P 三局、再 4P 三局，各 25–30 分钟。真人记录仍为空，自动呼叫脚本的作品/胶水是注入夹具。标记遮挡呼叫提示、屏边标签、生长手势重按规则、网络影响与学习效应，避免污染关键假设。完整证据及剩余退出警告见 `artifacts/b-package-r2-20260930-025527/verification.json` 和 `PROJECT_STATE.md` 最新条目。此时停止扩功能，下一步依赖真实协作反馈。
